# StayOra — Missing Features Audit & Complete Prototype Implementation

You are working on the existing **StayOra** project.

Your task is to **analyze the uploaded requirements/documentation file, identify features and capabilities that are missing from the current implementation, and implement those missing features completely as frontend prototypes.**

## Critical Rules

### 1. Do NOT break existing work

This is an enhancement task, **not a rewrite**.

Before making changes:

* Inspect the existing implementation.
* Understand how the current modules work.
* Reuse existing components, patterns, services, types and architecture wherever possible.
* Do not replace working features unnecessarily.
* Do not redesign existing modules unless a change is strictly required for integrating a missing feature.
* Do not remove existing functionality.
* Do not change existing behavior that is already correct.

**Prefer:**

```text
existing implementation → extend it
```

over:

```text
existing implementation → rewrite it
```

---

# 2. Use the Uploaded File as the Primary Source

Read and analyze the uploaded documentation completely.

Use it to identify:

* explicitly missing features
* missing roles
* missing permissions
* missing workflows
* missing capabilities
* documented implementation gaps
* incomplete functionality
* architectural gaps that affect the frontend prototype

Do not assume that something is missing simply because it is not obvious from one screen.

**Search the actual codebase before deciding a feature is missing.**

For every requirement from the document:

```text
Requirement from document
        ↓
Search existing implementation
        ↓
Already implemented?
   ├── YES → Do not unnecessarily modify it
   └── NO  → Implement it
```

If a feature is partially implemented:

```text
Existing partial implementation
        ↓
Complete it
```

Do not create a duplicate implementation.

# 3. Prototype Only

This phase does **NOT** require:

* database
* PostgreSQL
* Prisma
* backend
* REST API
* GraphQL server
* real authentication server
* real payment gateway
* external service integration

Everything should work as a **complete frontend prototype** using the project's existing mock/state architecture.

However, implement the prototype in a way that is **API-ready**.

The next development phase should be able to replace mock services/data with backend APIs without rebuilding the UI and business workflows.
