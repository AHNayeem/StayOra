Resolve the contradictions identified by the analysis, especially:

1. Admin catalogue vs public catalogue
   - Dashboard catalogue and public booking catalogue must use the same canonical prototype data/domain.

2. CMS publishing
   - Draft → Review → Publish must affect the prototype public experience.
   - Published content must be consumed through the same content abstraction rather than hard-coded UI constants where applicable.

3. Platform Settings
   - Commission, tax, service fee, cancellation/refund settings and similar configurable economics must come from a central configuration/service layer.
   - Avoid scattered hard-coded pricing constants.

4. System tools
   - Cron, queues, cache, storage and maintenance screens must behave as believable prototype simulations.
   - Do not claim real infrastructure exists.
   - Provide mock operational state/actions where appropriate.

5. Notifications
   - Notification actions should update a realistic prototype delivery lifecycle.
   - Preserve templates, preferences and delivery logs.
   - Clearly separate simulated delivery from real delivery.

6. Localization
   - Language switching must actually change application content, not only chrome.
   - RTL must work correctly where applicable.
   - Keep translations structured so a real i18n backend/content source can replace them later.

7. Finance
   - Establish one canonical prototype finance model.
   - Remove confusing duplicate/contradictory payout vs settlement behaviour.
   - All financial records should be traceable to bookings/merchants where applicable.

8. FX

   - Simulate rate locking instead of leaving the model unused.

9. Persistence
   - Standardize prototype persistence behaviour.
   - Features should survive refresh where persistence is expected.
   - Avoid having some modules use fake transient state while others use persistent domain state without a valid reason.

10. Roles
   - Make all existing defined roles demonstrable through seed/demo accounts and appropriate permissions.
   - Do not weaken RBAC just to make screens accessible.

↓

↓

- audit events
- consistent IDs/references
